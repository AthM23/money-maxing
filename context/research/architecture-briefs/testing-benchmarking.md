## Good practice for agent evaluation (and where it lands in the design)

- **pass^k, not pass@k.** tau-bench (arXiv 2406.12045) defines pass^k = all k independent trials succeed, graded by comparing the final database state to a goal state; gpt-4o was under 50% pass^1 and under 25% pass^8 on retail. APEX-Accounting shows the same collapse (2.6% Pass^8). This is the 0.95^80 slide as a metric. Footnote: k = 5 seeds per scenario, report pass^1 and pass^5, graded on ledger state and route, never on prose.
- **Variance before gains.** Miller, "Adding Error Bars to Evals" (arXiv 2411.00640): treat cases as a sample, report standard errors, cluster by scenario, use paired differences for A/B, check power. With 115 cases a 3-point move is noise; measure the run-to-run spread of the unchanged system first (a Syndicate winner did exactly this).
- **Deterministic graders first.** Anthropic's agent-eval guide: code graders are fast and reproducible, model graders need calibration against humans; grade the outcome, not the path; read transcripts. Footnote grades route, posted lines in integer cents and named rule ids in code. An LLM judge is allowed only for G-12 (explanation restates the input) and flux-note wording, from a different model family, with a reference answer and a human spot-check.
- **LLM-judge pitfalls.** Position, verbosity, style and self-preference bias (arXiv 2410.21819, 2412.05579). Use binary reference-guided criteria, a judge from another provider, never a judge on safety metrics.
- **Held-out and adversarial sets.** Reckon's 60 designed decoys and Meridian's 30 held-out validators were what judges rewarded. Hold out whole entities (vendors, customers) and whole cases from the learning loop; split by time.
- **Contamination and leakage.** Our data is synthetic, so the risk is not pretraining contamination but (a) an agent or the learning loop reading the answer key and (b) a tuned model learning the generator. Keep the key outside every tool root; scorer read-only; report on held-out entities and on a second seed.
- **Cost and latency as first-class results.** Vals and APEX publish cost beside accuracy. Report dollars, model calls and p50/p95 latency per decision by router tier, and cost per 1,000 transactions vs the model-only baseline.
- **Reproducibility.** Recorded model calls (cassettes), committed run artifacts, one-line repro, unflattering numbers kept.
